# 宿主（小米浏览器 20.27.1010901）hook 目标核对

本文件是 `HookBrowser` 1.5.0 的依据记录：所有 hook 点都在这个宿主版本上实测核对过。
宿主升级后照本文件的命令重跑一遍，即可确认哪些 hook 失效。

## 核对用的命令（无 JDK 环境）

用 `apk-static-analysis-windows` skill 里的脚本，全部纯 python、不需要解压整个 APK：

```bash

S="<apk-static-analysis-windows skill 目录>/scripts"
APK="<小米浏览器 20.27.1010901 官方 APK>"

# ① 某类声明了哪些方法（跨全部 dex）
$PY "$S/classmethods.py" "$APK" "(PremiumOperationManager|SimpleVersionHomeLayout|SystemSplashAd)"
# ③ 可加方法名正则筛选
$PY "$S/classmethods.py" "$APK" "search/interaction/settings/SearchModuleSettings" "isPersonalized"
# ④ 谁声明了这个方法名 —— 用来判「hook 目标到底在不在」
$PY "$S/findmethod.py" "$APK" "^requestGameRecommend$"

# ⑤ 字节级交叉验证「某类是不是真的没有 class_defs」（防脚本判读错误）
$PY - <<'EOF'
import zipfile
z = zipfile.ZipFile(r'<小米浏览器 20.27.1010901 官方 APK>')
key = b'Lcom/android/browser/quicksearchbox/data/HotSearchAdVersionData;'
```

读方法体：先 `dexdis.py <classesN.dex> <out> --filter '^Lcom/x/Y;'` 反汇编，再 grep 方法定义行
（`--filter` 匹配的是**类描述符**，写方法名永远 0 行）。

## 关键发现

### 1. base.apk 的第 4 组 hook 其实是「下载弹窗游戏推荐」

`requestGameRecommend()` 声明在 `com.android.browser.download.CommonDownloadDialogImpl`
（classes7.dex，无参 void），与同类的 `mGameRecommendCard` / `mGameRecommendList` /
`mRecommendingDownloadBtn` 字段配套 —— 是**下载弹窗里的游戏推荐卡片**，与搜索无关。
所以它属于「下载弹窗」开关，`ui_download`。

### 2. 搜索广告的真实链路（应用建议）

#### 主拦点：`SugCardData#a()`

`com.android.browser.quicksearchbox.data.SugCardData`（classes.dex）全文反汇编：

#### 兜底：展示层 `RecentAppManager`

搜索框下拉里那些带「安装」按钮的卡片，数据走**应用建议**链路：

```

  → RecentAppVersionData#getRecentAppData(Context)      读落盘 JSON          (classes.dex)
  → RecentAppManager#initNetworkList()                  反序列化 → mNetworkLists
  → RecentAppManager#initRecentAppList()                ★ 分流 + 固定插位
  → RecentAppManager#getRecentAppList()                 UI 取数（拷贝 mRecentAppList，上限 10 条）
```

`initRecentAppList()` 反汇编要点（classes.dex，`private synchronized`，同时刻只能被一处调用）：

```
遍历 getNetworkAppList()（= mNetworkLists 逐项展平）
  → 逐项判定 RecentApp#isAd()
       true  → 加入 mRecentAdAppList，并从 mOptionalAppList 移除
       false → 留在 mOptionalAppList
把 mRecentAdAppList[0] 插到 mOptionalAppList 的 index 1   ← 固定广告位
把 mRecentAdAppList[1] 插到 mOptionalAppList 的 index 4   ← 固定广告位
```

`RecentApp#isAd()`（classes9.dex）：

```java
public boolean isAd() {

    return a != null && !TextUtils.isEmpty(a.getExt());

```

截图卡片上那行「广告」字样就是 `ads.ext`。

**兜底的必要性**：短路 `a()` 只阻止「再次刷新」，若 `KvPrefs.display` 在模块生效前
就已经被写成 `true`，它不会自己关回去 —— 这时候靠展示层过滤兜住。

`isAdvertisingEnabled`（硬编码 `"true"`）只在 `HotSearchVersionData` 里出现，属于**另一条**
（推荐热词）链路，且实测那条在宿主 20.27 已废弃（见下节）。

### 3.5 错误页（「无法访问」）的「热搜榜」（1.9.7 新增）

错误页**不是普通网页**，而是一个 **hybrid 页**：native chromium 把 HTML 模板
`res/raw/miuichromium_error_page.html`（119,682 字节，UTF-8 解码后 119,044 字符，**单行无换行**）
读出来给 WebView 渲染，页面里的 JS 再通过 JavaScriptInterface 反向问宿主要数据。

#### 链路（已逐条反汇编确认）

```
JS 侧   utils.excuteClientAction(name, params?)
          = function t(e,t){ if (window.MiHybrid && window.MiHybrid.supportAction(e))
                             return window.MiHybrid.send("nativechannel://"+e+(t?"?params="+t:"")) }

        HybridActionDispatcher#send(String)  → 只是转调 call(String)
```

四个目标 action **全部直接继承 `java.lang.Object` 并实现 `IAction`**（`.super` 均为 `Ljava/lang/Object;`），
不是 `HybridAction` 子类 → 走「当前线程 dealAction」分支 → **返回值即 JS `JSON.parse` 的输入**。
四者的 `parseActionBean` 分别返回 null / `Params`，`shouldSafeIntercept()` **全部返回 false**。

#### 模板 JS 的渲染判据（逐字核验）

```js
e = JSON.parse(o.excuteClientAction("getDefaultPageInfo"));   // idx 112973（全模板唯一）

_ = e.isHotSearchAddImport || !1;                             // idx 113056（全模板唯一）★

0 === e.sceneType && e.realTimeHotSpotSwitch && ((_ ? c : n)(), E = 0);   // ← 出现 2 次（113280 / 113645）
1 === e.sceneType && e.guessYouWantSwitch &&
    ( 取 getGuessYouWantToSearchData → predictWords, E = 1, l.length || ((_ ? c : n)(), E = 0) );
```

渲染总条件 `d && ["a","c"].includes(e.type) && 0 < l.length && r.appendChild(...)`：

| `_` | `E` | 渲染出来的是 |
|---|---|---|
| `true` | 任意 | `hot_search_list` / 标题**「热搜榜」**/ `data-action="newJump"` → 跳**大米搜索（DJY）** |
| `false` | `0` | `search_result` / 标题「搜索发现」/ `data-action="jump"` |
| `false` | `1` | `want_search` / 标题「猜你想搜」/ `data-action="jump"` |

即 **`_`（`isHotSearchAddImport`）是「热搜榜」的唯一开关**。三处数据解析判据：

- `n()`：`"0" === e.code && e.data.searchbarkeywords` → `slice(0,10)`
- `c()`：`"success" === e.msg && e.data.itemList` → `slice(0,10)`
- 猜你想搜：`0 === e.status && e.data.predictWords` → `slice(0,8)`

#### 1.9.7 采用的 hook 点

**改返回值，不拦调用**：挂 `HybridActionDispatcher#call(String)` 的 after，把返回值里
`isHotSearchAddImport` 改成 false。理由：

1. 只动一个布尔 —— 错误提示、`container` 的 `switchOn` 类、以及
   `refresh` / `check` / `localCheck` / `clean` / `detail` / `research` / `inKidsMode` 等按钮全部不受影响；
2. 「搜索发现」「猜你想搜」是真搜索建议，保留（它们要 `_ === false` 才跑得到，正是我们制造的状态）；
3. 比改 `ErrorPageResource#getLoadErrorPageContent()` 的 119 KB 模板字符串稳 —— 那个是
   **static** 方法（`access=0x9`），hook 得到，但模板一换版正则就静默失效，且改错了直接白页。

> **备选方案（未采用，留给宿主换版时应急）**：二进制 patch 模板。锚点 `excuteClientAction:t}}()`
> 在模板里**全文件唯一**（已用 APK 内 `res/raw/miuichromium_error_page.html` 原文校验，
> sha1 `20682973ac0d25d6adb057689f9d8579ae09512b`，与工程 `.tmp/` 下解出的那份逐字节一致），
> 可替换为：
> ```js
> excuteClientAction:function(e,n){var c=t.apply(null,arguments);
>   if("getDefaultPageInfo"===e)return JSON.stringify({guessYouWantSwitch:0,
>     realTimeHotSpotSwitch:0,searchEnabled:0,sceneType:0,isHotSearchAddImport:0});return c}
> ```
> 注意 `call()` 返回的 JSON 若为 null 会抛异常被 catch 吞掉（模板不再渲染，不影响错误提示显示）。

### 3. 搜索框「广告热词」在宿主这边已下线

- `HotSearchManager.mNetworkAdLists`（广告词）只在 `initHotSearchAdList()` 里赋值；
- 而 `initHotSearchAdList()` 的唯一数据源是 `HotSearchAdVersionData`，

### 4. base.apk 全量 hook 清单（1.5.2 重新核对，无遗漏）

之前几次解析 base.apk 都受一个坑干扰：**StringFog 加密串以外，还有大量明文方法名
（`onCreate`、`getDebugMode`…）恰好满足「全 base64 字符集 + 长度 4 的倍数」**，

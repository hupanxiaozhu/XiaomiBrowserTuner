三个 Xposed 模块工程（多看调谐器 / 小米浏览器 / 番茄）的界面风格与胶囊动效统一规范。

- **设计基准**：`DuokanTuner`（多看调谐器）。色板、间距、圆角、字体全部以它的 `Ui.java` + `@color/miuix_*` 为准。
- **胶囊实物来源**：`XiaomiBrowserTuner`（本工程）（唯一真正有胶囊的工程：M3 `ActiveIndicator` 导航指示器 + 标签 pill）。
- **落地版本**：多看 1.23（code 24）/ 浏览器 1.9.6（code 27）/ 番茄 7.2.7（code 72336）。

## 三、胶囊规格

### 3.1 形状：stadium（圆角 = 高度 / 2）

| 用途 | 高度 | 圆角 | 左右内边距 | 字号 |
| --- | --- | --- | --- | --- |
| **标签胶囊** TAG（状态 / 版本 / 更新日志 tag） | 22dp | **11dp** | 10dp | 11sp |
| **动作胶囊** CHIP（页头轻量按钮） | 32dp | **16dp** | 16dp | 14sp |
| **导航指示器** NAV（底栏选中态） | 由内容撑开（图标 22 + 间隙 3 + 文字 ≈ 15 + 上下内边距 6×2 ≈ 52dp） | stadium | 12dp | 11sp |

**不要**再用「给一个远大于高度的圆角让渲染层收敛」的写法。它确实能出全圆（Skia 的
`setRectRadii` 会按比例缩放超限圆角），但**代码里读不出最终圆角**，改高度时没人知道要同步改这个数。
高度已知就用令牌直接算；高度由内容撑开（导航指示器）才退而用大圆角。

### 3.2 配色

| 状态 | 底色 | 文字色 |
| --- | --- | --- |
| 开 / 强调 | `accent_soft` | `accent` |
| 关 / 中性 | `track_off` | `text_sub` |

### 3.3 动效

| 动效 | 时长 | 插值 | 说明 |
| --- | --- | --- | --- |
| 状态胶囊切换 | **220ms** | 减速（Decelerate / `LinearOutSlowInEasing`） | 底色与文字色**同一条时间轴**插值 |
| 底栏指示器 | **260ms** | 减速 | 底色 0 → 12% + 缩放 0.88 → 1 同时进行 |
| 按压反馈 | 系统默认 | — | 多看用 `RippleDrawable(#14000000)`；XML 侧走 `?attr/selectableItemBackground`；Compose 走 `clickable` 默认 indication |

**插值起点的规则**：胶囊只有开 / 关（选中 / 未选中）两态，所以起始色**固定取「另一态」的颜色**
即可得到正确的前一帧 —— 不需要给 View 挂当前色状态，也就不怕被别处的 `setBackground` 弄脏。

**三种「不要放动画」的场合**（三个工程都必须处理，否则会看到闪烁）：
1. 刚打开详情弹窗时 —— 界面值已经是终态，再插值就是从对态闪一下；
2. 外部改了开关后重新对齐（如风险确认框异步落盘）—— 同理；
3. 点了切换但被拦下、状态其实没变 —— 用「上一次渲染出去的状态」判断是否真的翻转。

## 四、各工程落点

### 4.1 多看 DuokanTuner 1.23（基准，补齐胶囊）

唯一改动的文件是 `app/src/main/java/com/example/duokantuner/Ui.java`：

| 新增 | 说明 |
| --- | --- |
| `CAPSULE_TAG_H` / `CAPSULE_CHIP_H` / `CAPSULE_TAG_PAD_H` / `CAPSULE_CHIP_PAD_H` | 尺寸令牌 |
| `NAV_PILL_PAD_V` / `NAV_PILL_PAD_H` / `NAV_ICON_DP` | 底栏指示器令牌 |
| `DUR_CAPSULE_STATE`(220) / `DUR_CAPSULE_NAV`(260) | 动效令牌 |
| `capsule(c, colorRes, heightDp)` / `capsuleColor(c, color, heightDp)` | stadium 底，圆角按高度算 |
| `capsuleAuto(c, colorRes)` | 高度由内容撑开时用（底栏指示器） |
| `statusPill(c, on)` / `setStatusPill(c, tv, on, animate)` / `applyPill(...)` | 状态胶囊 + 220ms 颜色过渡 |
| `TAG_NAV_PILL` / `TAG_NAV_ICON` / `TAG_NAV_LABEL` | 底栏三层结构的 tag 锚点 |

改造：
- `chip()` 改走 `CAPSULE_CHIP_H` 令牌；
- `detailDialog()` 的状态 TextView 换成 `statusPill` + `setStatusPill`（`firstPaint` 标志控制首次不动画）；
- `bottomNav()` 的 item 由 `LinearLayout` 改成 `FrameLayout`（热区 + 涟漪）包一个 `pill`
  （`wrap_content`，胶囊层）—— 给 item 直接设背景会拉满整列、变成长条；
- `paintNavItem(c, item, selected, animate)` 增加 `animate` 形参，首次构建直接落终态；
  `updateNav()` 传 `true`。
- 底栏动画用 `ViewPropertyAnimator`：`View.setScaleX/setAlpha` 会顺带取消上一个 animator，
  连点两栏不会叠动画，不需要自己管理 `Animator` 实例。

| `ui/Changelogs.kt`、`CHANGELOG.md`、`README.md` | 版本与日志 |

`PrefsFragment` 的两条实现要点：
1. 弹窗改用 `setOnShowListener` + 手动 `setOnClickListener` 接管 positive button
   （不用 `setPositiveButton(label) { ... }`，那个点完就关窗；但**必须**保留
   `setPositiveButton(label, null)`，否则 `getButton(BUTTON_POSITIVE)` 返回 null）；
2. 自己发起的 SP 写入要用 `suppressingExternalSync` 挡掉 SP 监听里的「外部同步」——
   `SharedPreferencesImpl` 在主线程 `apply()` 时是**同步**回调监听器的，不挡的话刚起步的
   过渡动画会在同一帧被拍回终态，等于没动画。
3. `OnDismissListener` 里把 `externalSync` 置空，别让弹窗关了还持有已回收的 View。

全部改在 `app/src/main/java/cc/hookfanqie/compat/ui/SettingsScreen.kt`：

| 位置 | 改动 |
| --- | --- |
| `SettingsRoute()` | 改用统一的 `UnifiedLightScheme` / `UnifiedDarkScheme` 覆盖 miuix 默认值 |
| `VersionTag()` | `RoundedCornerShape(8.dp)` + `secondaryContainer` → `CAPSULE_TAG_SHAPE`(percent 50) + `primary` 12% 底，高 22dp、左右 10dp |
| `SectionCard()` | 16dp → `CARD_RADIUS`(20dp) |

| `CapsuleNavBar()` / `CapsuleNavItem()` | **新增**：替换 miuix `NavigationBar`，56dp 高、选中项套 12% accent 胶囊并做 260ms 淡入 + `0.88 → 1` 缩放 |

`UnifiedLightScheme` / `UnifiedDarkScheme` 覆盖的三处 miuix 默认值（它们与另两工程不一致）：
- `surface` 默认 `#F7F7F7` → `#F2F2F7`；
- `onBackgroundVariant` 默认 `#8C93B0`（偏蓝灰）→ `#858585`；
- 深色 `surfaceContainerHigh` 默认 **等于** `surfaceContainer`（都是 `#242424`）→ `#3A3A3C`。
  这一条顺带修掉一个既有缺陷：详情弹窗的「注意事项」块在深色下与卡片同色、**等于看不见**。

Compose 侧不引入 compose-animation 依赖，用 `animateFloatAsState` + `lerp`（`ui-graphics` 自带）
代替 `animateColorAsState` —— 只是两个颜色之间的线性插值，用不着整个动画库。

## 六、踩过的坑（改之前先看这一节）

1. **miuix 0.9.2 的底栏没有指示器**。别再试图在 `NavigationBarItem` 上找 indicator 相关参数 ——
   源码 `commonMain/top/yukonga/miuix/kmp/basic/NavigationBar.kt` 里压根没有。要胶囊只能自绘。
2. **XML 里的 `100dp` 圆角能出全圆，但不可读**。Skia 会按比例缩放超限圆角，所以它「碰巧」是对的；
   一旦有人改了控件高度，这个数字就没人知道该改成多少。
3. **`MaterialAlertDialogBuilder` 不 `setPositiveButton` 就拿不到按钮**。
   想自己接管点击，仍然要给一个 label（传 `null` 作为 listener），否则 `getButton()` 返回 null。
4. **`SharedPreferencesImpl.apply()` 在主线程是同步回调监听器的**。用 SP 监听来同步 UI 时，
   自己发起的写入必须显式挡掉，否则动画会被同一帧的「重新对齐」打断。
5. **miuix 深色下 `surfaceContainerHigh == surfaceContainer`**。任何「用 `surfaceContainerHigh`
   当块底、`surfaceContainer` 当卡片」的写法在深色下都会看不见 —— 必须覆盖色板。
6. **`RoundedCornerShape(percent = 50)` 才是 Compose 里的 stadium**，`RoundedCornerShape(11.dp)`
   只在高度恰好 22dp 时等价。
